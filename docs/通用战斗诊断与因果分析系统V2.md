# 通用战斗诊断与因果分析系统 V2

## 目标

V2 将战斗记录、Boss 机制识别、指标计算、重叠归因、长尾变化点、队伍功能损失、A/B 实验和证据结论拆成独立模块。报告逻辑不得按 Boss 名称硬编码。

## 配置入口

- `config/combat-metadata-v2.json`：精灵职能权重和 Boss 原型标签。
- `config/metrics-v2.json`：指标定义、来源事件、聚合与缺失值规则。
- `config/boss-mechanics-v2.json`：Boss 机制窗口 DSL 与归因规则。
- `config/diagnostics-v2.json`：变化点、长尾和功能损失阈值。
- `config/experiments-v2.json`：实验身份、可比字段和同 Seed 配对要求。

## 模块职责

- `event-v2.mjs`：将现有诊断 Trace 转换为 `CombatEventV2`，建立事件、行动和因果引用。
- `metadata-registry.mjs`：统一单位、技能和 Boss 元数据。
- `metric-registry.mjs`：指标注册和统一计算。
- `mechanic-dsl.mjs`：校验并读取通用 Boss 机制 DSL。
- `attribution-engine.mjs`：开启/关闭机制窗口，计算匹配基线并处理机制重叠。
- `change-point.mjs`：以基线、滑窗和持续条件识别真实变化点。
- `role-loss.mjs`：按队伍功能权重计算损失，不用角色名猜职能。
- `experiment-registry.mjs`：校验 A/B 可比性并执行同 Seed 配对。
- `ai-source-analysis.mjs`：拆分基础、通用、Boss 专属、资源、生存和防拖延评分来源。
- `evidence-engine.mjs`：输出事实、推断、反证、证据等级和允许设计动作。
- `quality-gates.mjs`：P0 门禁失败时阻断自动设计结论。

## 运行

```powershell
npm run report:boss:v2 -- --boss=FORGE_BOSS_WARRIOR --runs=100
```

复用已有 Trace：

```powershell
npm run report:boss:v2 -- --boss=FORGE_BOSS_WARRIOR --runs=100 --reuseFrom=validation-artifacts/example
```

迁移旧 Trace：

```powershell
npm run migrate:trace:v2 -- --input=validation-artifacts/example/diagnostic-trace.json --output=validation-artifacts/example/combat-events-v2.json
```

每次报告输出：`report.md`、`report.json`、`report-debug.md`、`representative-seeds.json`。

## 裁定边界

观察样本默认只支持 `Observe` 或 `Verify`。候选修改至少需要注册实验的同 Seed 配对；正式修改还需要满足样本、因果置信度和反证门槛。自动策略结果不替代真人测试。

## 默认入口与兼容

- `npm run simulate:boss:generic` 已切换为 V2。
- `npm run simulate:boss:generic:v1` 保留旧报告，便于过渡期对照。
- 旧 Trace 可通过 `npm run migrate:trace:v2` 转换；旧字段与旧报告没有删除。

## 已知限制

- 当前机制选择器支持事件类型、技能、状态、阶段、标签和元数据等值匹配，不支持任意布尔表达式、跨多个实体的状态机条件和脚本化聚合条件。
- 当前完成的是单 Boss 报告；数据合同已预留 `phaseId` 与多来源事件，但多 Boss、阶段连续继承和连战跨场归因尚未回归。
- 指标 DSL 支持注册事件筛选、字段求和、比例和外部权重；复杂统计模型需要先扩展通用指标算子，不能写 Boss 专属分支。
- 匹配基线当前使用存活数与资源档；战斗阶段字段已由事件协议预留，但现有三个 Boss 的配置尚未要求阶段匹配。
- 自动策略报告只用于设计诊断，真人体验仍属于 Level 4 独立证据。
