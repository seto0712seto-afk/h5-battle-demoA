# 战斗模块对接清单

版本：2026-08-12

## 结论

另一个项目负责关卡导航、账号进度和关卡奖励；本项目负责战斗配置、战斗结算与战斗 UI。双方只通过 `mountBattle()`、`StageEnemyConfig[]` 和 `PlayerBattleSnapshot` 对接，不复制战斗条件到关卡项目。

## 唯一调用入口

```ts
import { mountBattle } from './battleIntegration';

const battle = mountBattle({
  root: document.querySelector('#battle-root') as HTMLElement,
  selectedSpiritIds: ['P01', 'P02', 'P03', 'P04'],
  enemies: [
    { enemyId: 'FORGE_GRUNT_WARRIOR', position: 'front' },
    { enemyId: 'FORGE_GRUNT_SHOOTER', position: 'back_1' }
  ],
  battleSeed: 'stage-1:battle-1',
  onBattleEnd({ result, playerSnapshot }) {
    // 记录胜负；连续战斗时保存 playerSnapshot。
  },
  onResultAction({ result, playerSnapshot }) {
    // 玩家点击结算按钮后返回关卡，或进入下一场。
  }
});

// 页面卸载或切换场景时必须调用。
battle.stop();
```

连续战斗把上一场的 `playerSnapshot` 原样传给下一次 `mountBattle()`。单场战斗不传该字段。

## 输入契约

- `selectedSpiritIds`：1 至 6 个精灵 ID；前三个为首发。
- `enemies`：1 至 3 个 `StageEnemyConfig`。
- `position`：`front | back_1 | back_2`。
- `battleSeed`：关卡项目生成的稳定字符串或数字，用于复现随机行为。
- `playerSnapshot`：仅供连续战斗继承阵容、站位、生命、死亡与妖力。
- `telemetry`：可选，不接测试系统时可以不传。

## 输出契约

- `result`：`victory | defeat`。
- `state`：结束时完整战斗状态，只读使用。
- `playerSnapshot`：可供下一场战斗使用的清理后快照。

`onBattleEnd` 在战斗首次进入胜负状态时触发；`onResultAction` 在玩家点击结算按钮时触发。

## 不要迁移到正式运行包的内容

```text
scripts/
config/boss-report-*.json
config/diagnostics-v2.json
config/metrics-v2.json
config/experiments-v2.json
tests/
validation-artifacts/
desktop-release/
```

这些内容属于自动测试、数据诊断或发布产物。需要保留战斗回归能力时，可以把 `tests/` 和对应 `scripts/` 留在开发仓库，但不要进入运行时依赖。

## 合并检查

1. 新项目的 TypeScript 目标至少支持 ES2022 和 DOM。
2. 为战斗 CSS 增加独立入口或作用域，避免与关卡 UI 的全局类名冲突。
3. 不得在关卡项目重复定义技能条件、妖力规则、目标合法性和敌人 AI。
4. 精灵 ID、怪物 ID 和关卡 ID 必须保持唯一。
5. 场景退出调用 `stop()`，否则计时器仍会运行。
6. 连战只使用 `PlayerBattleSnapshot` 继承状态，不自行拼装生命和站位。
