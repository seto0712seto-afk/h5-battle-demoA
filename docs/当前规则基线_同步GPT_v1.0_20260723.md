## 1. 当前项目边界

1. 当前只维护一套核心战斗主线。
2. 旧系统1、系统2、异步行动条、五行破绽、四拍验证、R0随机实验等旧分支均不再进入运行工程。
3. 支持单场 Boss 挑战和五场连续副本；两者使用完全相同的底层战斗规则。
4. 项目为纯 H5 前端，无后端。
5. 当前不包含灵玉、装备、养成、道具效果、自动战斗、存档和软限时黑雾。
6. 黑雾仅作为未来所有战斗共用的底层软限时方向，尚未细化、尚未实现。

## 2. 战前队伍

1. 候选精灵共 10 只。
2. 玩家可以选择 1 至 6 只出战，不强制带满；未带满只做软提示。
3. 编队顺序前 3 只为首发，剩余为后备。选择不足 3 只时，已选精灵全部首发。
4. 每个首发按照自身默认站位进入前排或后排。
5. 一键战斗随机选择 6 只，默认首发固定为 1 名前排、2 名后排；三只后备中包含 1–2 名前排，禁止0前排或3前排；具体精灵及同组内排列顺序随机。
6. 战前只展示精灵配置、属性、技能与阵容预览，不再展示顶部 Boss 情报入口。

## 3. 回合与行动顺序

1. 当前使用完整回合制，不使用异步行动条积累。
2. 每回合开始时，为场上全部存活玩家单位和每只存活敌人各生成 1 个正常行动位。
3. 行动位按回合开始时速度从高到低排序并锁定；同速时按创建顺序处理。
4. 回合中的速度变化从下一回合开始生效。
5. 回合中换入或补位的单位不追加本回合行动位。
6. 全部行动位完成、失效或跳过后，进入回合结束和统一补位。
7. Boss 使用预告技能后，该 Boss 在下一回合移动到行动顺序最后；只影响下一回合一次。
8. 战斗界面左侧持续显示本回合完整行动顺序、当前行动者、已行动和待行动状态。

## 4. 团队妖力

1. 初始妖力为 0，上限为 10。
2. 玩家单位每次正常行动开始、出现操作选项前，团队获得 1 妖力。
3. 妖力达到上限时不溢出。
4. 额外行动不触发行动开始回妖力。
5. 技能确认后支付妖力；后续目标失效或效果落空不退款。
6. 技能回能只受妖力上限 10 约束，不存在每回合回能上限。
7. 妖力达到 5 在程序中称为“充盈阈值”，但没有全局通用效果；只有明确配置了该条件的技能读取它。
8. 当前读取妖力 5 条件的主要技能为铁甲犀的【铁壁防护】。

## 5. 三行、前后排与换宠

1. 玩家和敌方各有 3 个目标行；每行包含前排和后排位置。
2. 同一行的前后排视为同一个锁定目标行。
3. 前后排是当前战斗站位，可以由切换站位或换宠改变。
4. 正常行动可以使用技能、换宠或切换自身前后排。
5. 额外行动只能使用技能，不能换宠或切换站位。
6. 主动换宠时，新精灵按照自己的默认站位进入该目标行，不继承换出者的前后排。
7. 主动离场会清除离场精灵的临时战斗状态、护盾、连续使用记录和入场资格；生命保留。
8. 死亡单位立即离开格子，该行在本回合剩余期间保持空置。
9. 死亡单位尚未执行的行动位失效，不转移给其他单位。
10. 回合结束后按格子顺序选择存活后备补位；死亡补位按照换入精灵自己的默认站位登场，不继承阵亡者的前后排。
11. 场上全灭但后备仍存活时不立即失败；回合结束后继续补位。

## 6. 目标合法性与锁定

1. 当前玩家单体敌方技能共用前排限制：敌方存在存活前排时只能选择前排；敌方没有前排时才开放后排。
2. 敌方技能按自身配置优先选择玩家前排、后排或全体；优先排为空时回退到另一排。
3. 友方单体技能只能选择场上存活友方，不能选择后备。
4. 多段技能锁定原目标；目标死亡后剩余段数落空，不转移。
5. 行动来源在技能结算中死亡时，尚未开始的后续段和后续效果停止。
6. 预告锁定对象切换前后排后，锁定仍跟随该单位。
7. 预告锁定对象主动换宠后，兑现技能攻击原目标行上的新单位。
8. 原锁定对象仍在场时，其他目标行发生换宠不会改变锁定对象。
9. 原目标死亡且目标行为空时，兑现技能落空，不重新选取其他目标。
10. 界面必须明确显示预告技能、预计威力、锁定对象或目标行；被锁定棋盘位置需要明显标记。

## 7. 伤害、暴击、治疗与护盾

### 7.1 玩家普通伤害

```text
物理伤害 = ceil(技能威力 × 玩家物攻 ÷ 敌人物防 × 暴击倍率 × 爆发倍率 × 敌方受伤倍率)
魔法伤害 = ceil(技能威力 × 玩家魔攻 ÷ 敌人魔防 × 暴击倍率 × 爆发倍率 × 敌方受伤倍率)
最低伤害 = 1
暴击倍率 = 1.5
爆发倍率 = 1 + 爆发层数 × 0.25
```

### 7.2 敌方伤害

```text
敌方物理伤害 = ceil(技能威力 × 敌人物攻 ÷ 玩家物防 × 敌方伤害倍率)
敌方魔法伤害 = ceil(技能威力 × 敌人魔攻 ÷ 玩家魔防 × 敌方伤害倍率)
最低伤害 = 1
```

### 7.3 固定和额外伤害

1. 固定伤害不读取攻防，不暴击，也不读取攻击者的爆发倍率。
2. 固定和额外伤害仍读取目标身上的易伤、熔核破绽等受伤倍率。
3. 盾压消耗的护盾按 1:1 转化为额外固定伤害。
4. 所有最终伤害向上取整。

### 7.4 治疗和护盾

1. 百分比治疗以目标最大生命计算并向下取整。
2. 固定治疗直接增加对应数值，不超过最大生命。
3. 护盾可以持续叠加，受到伤害时优先消耗护盾。
4. 护盾完全吸收伤害仍视为受到攻击，可以触发蓄势。

## 8. 状态规则

1. 状态持续时间按状态持有者的正常行动次数计算。
2. 持有者在自身行动中获得的新状态，不在同一次行动结束时减少持续时间。
3. 同名不可叠状态只保留一份，持续时间和效果值分别取较高值。
4. 可叠状态累加层数，持续时间取较高值。
5. 主动离场和连战进入下一场时清除临时状态。

| 状态 | 当前效果 |
| --- | --- |
| 爆发 | 每层使攻击伤害提高25%；持续到持有者下一次正常行动结束。设计口径不设玩法上限，程序当前使用99层作为技术上限。 |
| 蓄势 | 持续1回合；每次受到攻击且未死亡时获得4层爆发，每次攻击都会触发。 |
| 回复 | 持有者正常行动开始时恢复10%最大生命；同名回复只存在一个。 |
| 护盾 | 数值可以叠加；默认在持有者正常行动结束时清除旧护盾，本次行动中新获得的护盾保留。 |
| 盾阵 | 存在时护盾不会在正常行动结束时清除；盾阵结束当次仍保留护盾。 |
| 易伤 | 目标受到最终伤害提高50%，即×1.5。 |
| 熔核破绽 | 熔核守卫使用熔核蓄力后获得；在其下一次行动开始前受到伤害×2。 |

## 9. 动态技能记录与按钮接口

1. 连续使用减费在技能确认时读取并更新。
2. 改用其他技能、换宠或切换站位会中断连续使用记录。
3. “本场第一次使用”每场战斗单独计算，进入下一场后刷新。
4. “每次入场后的首次技能”在每次从后备入场时刷新；第一次使用任意技能后消耗资格。
5. 登场刷新与本场首次使用是两种独立记录，不得混用。
6. 技能按钮统一读取战斗逻辑返回的：`usable / enhanced / enhanceReason / enhanceValue / targetDependent`。
7. 前端不得复制技能条件；费用、强化、目标依赖和实际威力均由战斗逻辑返回。
8. 标记为确认时判断的妖力条件，以技能最终确认、扣费前的妖力快照结算。

| 魔力脉冲 | 80 | 当前前排单体造成当前威力的魔法伤害；无前排时攻击后排。初始威力80。 |
| 魔力增幅 | 0，强制行动 | 每完成3次魔力脉冲后，下一次合法行动强制使用；脉冲当前威力永久+80并重置计数。 |

魔力增幅不创建状态、没有强化次数上限，威力依次为80、160、240、320……，只在本场战斗内保留。

## 14. 副本结构

1. 单场挑战：熔核守卫挑战、灰羽猎王挑战、炽印法主挑战。
2. 固定五场副本：熔核工坊、雷鸣矿区、苔生遗迹。
3. 随机五场副本：万象裂隙。
4. 固定副本前四场由主题小怪和精英怪组成，第五场为对应单独 Boss。
5. 万象裂隙前四场固定生成一只精英怪和两只小怪，并将这些敌人的本场最大生命调整为正式模板的 85%；第五场从三个 Boss 中随机选择。
6. 万象裂隙由 Seed 复现阵容；默认 Seed 为20260722。

## 15. 连战继承

1. 下一场保留已选队伍、当前场上阵容、当前前后排、生命、阵亡情况和团队妖力。
2. 玩家在上一场主动换过阵容时，下一场保持换后的配置，不重置为首场首发。
3. 下一场清除临时状态、护盾、技能冷却、连续使用、技能使用计数和战斗内成长。
4. 本场首次使用记录在下一场刷新。
5. 敌方生命、状态、预告、随机记录和运行时技能威力不跨场继承。

## 16. 胜负

1. 当前结算链全部完成后统一检查胜负。
2. 当前场全部敌人死亡且玩家仍有存活精灵时胜利。
3. 玩家所选全部精灵死亡时失败。
4. 同一结算链双方全部死亡时判定敌方获胜。

## 17. 当前 UI 规则

1. 玩家与敌方使用对称六格棋盘；中央位置统一显示为3，不再显示3A/3B。
2. 后备生命放在棋盘外独立区域，避免破坏棋盘对称。
3. 棋盘常驻信息只显示身份、生命、行动状态和必要战斗状态。
4. 点击敌方单位只展示属性系数与状态详情；等级、职业、权重和技能规划信息不在战斗弹窗展示。
5. 技能按钮、技能详情和战前技能使用同一数据格式。
6. 友方单体技能可以直接点击玩家棋盘确认目标。
7. 行动时大 UI 保持静止，只允许单位小图标、弹道、受击抖动、飘字和局部状态动画。
8. 预告蓄力必须显示技能名、锁定对象或目标行、预计威力，并有局部呼吸动态。

## 20. 推荐协作同步流程

1. **GPT设计阶段：** GPT只能输出带版本号的“设计提案”，不得直接覆盖当前规则基线。
2. **殿下确认阶段：** 将采纳项整理成短任务单，明确“替换、保留、删除、暂不实现”。
3. **Codex实现阶段：** Codex对照任务单修改代码、测试和界面，不擅自扩展。
4. **Codex回填阶段：** 测试通过后更新本文件、同步编号和变更记录。
5. **再次咨询GPT：** 每次新对话先发送最新版规则基线，再发送本轮设计问题。

必须把以下三种状态分开：

- **当前规则：** 已实现并测试，可作为事实引用；
- **已确认待实现：** 殿下确认，但代码尚未完成；
- **设计候选：** 仅供讨论，不能视为项目事实。

建议每次改动使用统一编号，例如：

```text
CHANGE-20260723-01
目标：高温爆发威力300→200
状态：已实现 / 已测试 / 已写入基线
影响：Boss配置、预告威力、自动化测试、同步文档
```
